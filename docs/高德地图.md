**# AMap H5 / PC 地图 Skill**

**## Skill 定位**

本 Skill 是一个可复用的高德地图能力 Skill。

它负责将真实的高德地图能力接入宿主 H5 / PC Web 项目，不负责宿主项目的业务体系。

核心原则：

\> 只负责真实展示地图、真实获取位置、真实完成地图交互，并将标准地图结果交给宿主项目。

\---

**## 触发条件**

当用户需求出现以下任意场景时，启用本 Skill：

\- 地图

\- 高德地图

\- AMap

\- 显示位置

\- 位置展示

\- 地图标点

\- 地图定位

\- 获取当前位置

\- 经纬度展示

\- 轨迹展示（仅地图绘制部分）

\- 周边范围

\- 画圈范围

\- Marker

\- InfoWindow

启用后必须执行本 Skill 的完整规则，不得只生成地图占位区域或静态地图图片。

**## 技术默认值**

**### 1. 核心原则**

本 Skill 只负责真实的高德 AMap JS API 2.0 地图能力。

真实地图必须使用有效的高德地图 Key。  

但是：

\- **\*\*不得要求用户直接在聊天中发送高德 Key\*\***


\- **\*\*不得让非开发用户打开 HTML 源码寻找位置填写 Key\*\***

\- **\*\*不得把 Key 当作普通业务参数暴露在页面 UI 中\*\***

\- **\*\*不得把 Key 输出到聊天、日志、错误信息、README、注释或其他可见文本中\*\***

\- **\*\*不得使用假 Key、虚拟 Key、假地图或伪造坐标冒充真实地图\*\***

\- **\*\*不得在没有 Key 的情况下声称“真实地图已经配置完成”\*\***

Skill 必须先解决“Key 如何安全配置”的问题，再生成真实地图。

\---

**### 2. 生成真实地图前必须执行配置检查**

触发本 Skill 后，AI 必须先判断当前项目/宿主环境是否已经存在高德地图配置。

配置状态分为：

\`\`\`text

AMAP\_CONFIGURED

    已存在有效配置，可以继续生成/运行真实地图

AMAP\_NOT\_CONFIGURED

    没有可用配置，需要进入配置流程

AMAP\_TEMPLATE\_MODE

    用户明确要求先生成没有 Key 的代码模板

\`\`\`

如果状态为：

\`\`\`text

AMAP\_CONFIGURED

\`\`\`

则直接继续地图生成，不得重复要求用户提供 Key。

如果状态为：

\`\`\`text

AMAP\_NOT\_CONFIGURED

\`\`\`

则不得直接生成一个需要用户自己修改源码才能运行的“完整地图”。

必须先向用户说明需要高德地图 Key，并引导用户进入安全配置方式。

\---

**### 3. 不允许通过聊天消息收集 Key**

以下做法均禁止：

\`\`\`text

“请把你的高德 Key 发给我”


“把下面这个 Key 发给 AI”

\`\`\`

即使用户主动提出把 Key 发到聊天中，也不应将其作为默认配置流程。

如果用户已经在聊天中提供了 Key：

\- 不要在回复中重复完整 Key

\- 不要主动展示完整 Key

\- 不要把 Key 写入说明文档

\- 不要把 Key 输出到日志

\- 如果宿主环境提供安全配置能力，应优先引导用户改用安全配置

\- 如果当前环境无法安全保存该凭证，应明确告知限制，而不是继续扩散凭证

**#### 第一优先级：宿主平台 Secret / 安全配置**

如果当前 AI 编程平台、项目生成平台或宿主系统提供：

\`\`\`text

Secret

安全变量

密钥管理

项目凭证

\`\`\`

推荐配置名称：

\`\`\`text

AMAP\_SECURITY\_JSCODE

\`\`\`

其中：

\`\`\`text

AMAP\_KEY

\`\`\`

表示高德地图 Web 端 JS API Key。

\`\`\`text

AMAP\_SECURITY\_JSCODE

\`\`\`


用户应在宿主平台提供的安全配置界面填写，而不是通过聊天发送。

\---

**#### 第二优先级：项目提供独立配置入口**

如果宿主平台没有 Secret / 安全变量能力，但项目运行环境允许提供配置页面，则应提供独立的：

\`\`\`text

\`\`\`

例如：

\`\`\`text

\`\`\`

\- 明确说明为什么需要高德 Key

\- 提供 Key 配置入口

\- 对 Key 使用密码类型输入

\- 默认不显示完整凭证

\- 不把 Key 作为普通业务数据展示

\- 提供配置状态检查

\- 提供地图连接测试

\- 提供配置成功/失败提示

\- 不要求用户修改 HTML 源码

注意：

如果项目是纯静态 Web，并且没有后端或宿主 Secret 能力，则浏览器端无法提供真正意义上的服务端 Secret 存储。

因此，Skill **\*\*不得宣称纯静态页面能够绝对安全地隐藏高德 Key\*\***。

此时应将其定位为：

\`\`\`text

部署配置

\`\`\`

而不是：

\`\`\`text


\`\`\`

**#### 第三优先级：集中式配置文件**

如果项目明确要求由开发人员部署配置，并且用户接受修改项目配置，则允许使用统一配置文件。

例如：

\`\`\`text

\`\`\`

\`\`\`javascript

\`\`\`

\- 所有地图页面统一读取该配置

\- 禁止每个 HTML 页面重复填写 Key

\- 禁止把 Key 散落在多个 JS 文件

\- 禁止运行时创建多个 Key 配置入口

\- 配置文件必须有明确注释说明用途

\- 不得把真实 Key 写入 README、示例代码或文档正文

该方式主要面向开发人员或部署人员。

\`\`\`text

**## SDK 规则**

本 Skill 默认使用高德官方线上 JS API 2.0。

要求：

- 使用高德官方 JS API 2.0
- 使用官方 `webapi.amap.com` 资源
- 不要求 npm install
- 不要求 pnpm install
- 不要求 yarn install
- 不要求 npm run build
- 不要求 `@amap/amap-jsapi-loader`
- 不要求本地下载高德 SDK
- 不要求自建 CDN 镜像
- 地图 SDK 的访问凭证由宿主项目或部署环境自行负责
- 本 Skill 不规定凭证的申请、存储、输入、展示或传递方式
- 宿主项目如果已经完成 AMap SDK 配置，地图 Skill 直接复用现有配置

本 Skill 不应要求最终用户在地图页面中填写任何地图访问凭证。

**## 地图 SDK 加载失败**

任何地图初始化或地图相关动作前，都必须检查：

\`\`\`javascript

typeof AMap === 'undefined'

\`\`\`

如果 SDK 不存在：

\- 不得执行 \`new AMap.Map\`

\- 不得抛出未捕获异常

\- 不得向用户显示 \`AMap is not defined\`

\- 不得自动切换其他地图 SDK

\- 不得动态插入备用远程脚本

统一提示：

\> 地图组件加载失败，请检查网络后重试

提示后必须恢复可交互状态。

不得在页面初始化时因为 SDK 加载失败立即弹窗；应在地图功能实际触发时进行检测与提示。

**## 定位规则**

使用：

\`\`\`javascript

AMap.Geolocation

\`\`\`

定位必须遵循：

\`\`\`text

用户主动点击定位

    ↓

检查地图 SDK 和浏览器环境

    ↓

申请定位权限

    ↓

用户允许

    ↓

获取真实坐标

    ↓

地图移动到当前位置

    ↓

添加当前位置 Marker

    ↓

向宿主输出 lng / lat

\`\`\`

禁止：

\- 页面加载自动申请定位

\- 绕过系统权限

\- 伪造定位结果

\- 写死坐标

\- 随机生成坐标

\- \`setTimeout\` 模拟定位

\- 无限重复请求定位

地图本身允许页面加载时初始化，但定位必须由用户主动操作触发。

\---

**## 定位错误分类**

不得所有错误都只显示“定位失败”。

至少区分：

\- 用户拒绝权限  

  \`定位权限未开启，请允许本页面使用定位后重试\`

\- 浏览器不支持  

  \`当前浏览器暂不支持定位，可在地图上手动查看位置\`

\- 定位超时  

  \`定位超时，请检查网络或移步空旷处重试\`

\- 无法获取位置  

  \`暂时无法获取您的位置，请稍后重试\`

定位失败后必须保留地图，并提供重新定位能力。

\\\`\\\`\\\`text

4\\. **\*\*\\\*\\\*禁止事项\\\*\\\*\*\***：
